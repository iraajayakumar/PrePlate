# Backend testing

The backend tests use H2 and do not require a running MySQL server. From the repository root, run:

```powershell
Push-Location backend
.\mvnw.cmd test
Pop-Location
```

For a package build without rerunning tests:

```powershell
Push-Location backend
.\mvnw.cmd -DskipTests package
Pop-Location
```

The test suite includes unit tests for authentication, meal schedule rules, forecasting calculations and request mapping, ML details parsing/validation, waste metrics, and notifications. Spring Boot integration tests exercise authentication, student meal responses and preferences, admin access, notifications, consumption/waste analytics, concurrent response handling, and forecasting with ML success, ML fallback, HTTP errors, timeout/connection failures, malformed responses, missing history, and check-ins while the ML service is down. ML HTTP tests use `MockRestServiceServer` and do not require a live Python service.

The integration test profile uses an in-memory H2 database and a fixed clock (2026-11-14 13:40, Asia/Kolkata) so deadline behavior is deterministic. The runtime schema is not generated by Hibernate; tests provide their own H2 schema. Production/local runs should initialize MySQL using `database/schema.sql`, `database/seed.sql`, and then `database/migration_01_ml_forecast.sql` before starting the application.

## Manual ML service smoke test

From `forecast-service/`, create a Python 3.13 virtual environment, install dependencies, run the service tests, and start FastAPI:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

In another PowerShell terminal from the repository root, send the checked-in sample request to the detailed endpoint:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8000/forecast/details -Method Post `
  -ContentType "application/json" -InFile forecast-service/sample-request.json
```

The backend defaults to the ML service being enabled at `http://127.0.0.1:8000` with a 5-second timeout and `servings` as the item unit. Confirm `preplate.forecast.enabled=true` in the active backend configuration, apply the database migration after the base schema, then start the backend. Dashboard and refresh requests exercise the integration; student check-ins do not call the forecasting service.
